## 题目

这是流程终面阶段的一场 45 分钟胜任力面试，主持人是人力与文化伙伴（people-and-culture partner），或者
另一位接受过“Googleyness and leadership”评分标准培训的面试官。这一轮考察的是，支撑你走过技术轮的那些
特质，放到你怎么和人共事、怎么在模糊情境（ambiguity）下展现主人翁（ownership）意识、怎么在压力下应对
时，是不是依然成立，而不是把技术能力再考一遍。大多数问题都要求你讲述自己过往经历里的一个真实情境，而
不是一个假设情境，面试官期望你用情境、任务、行动、结果（STAR）的结构来组织回答；面试官的追问会越过
故事表面的情节，探究你自己具体的行动、这些行动确实带来了你所说效果的证据，以及你事后从中学到了什么。
也有少数问题要的是一个明确的回答或立场，而不是一个故事——使命、AGI、你的长期规划，以及领导力与团队
这一组里的大部分问题——并且期望它有一个具体例子支撑。“为什么是 Google DeepMind”在这里会被问得比 HR 初筛时更深入。问题分为六组。

### 动机与使命

- 为什么是 Google DeepMind，为什么是这个团队，为什么是你职业生涯的这个节点——把答案落到一个你已经因为
  这个原因做出的决定上，而不是把 HR 初筛时说过的话再讲一遍。
- 讲一次你日常工作被“安全且负责任地”（safely and responsibly）构建 AI 这件事影响的经历——它改变了一个
  具体的决定，而不只是你抽象持有的一个信念。
- 说出 Google DeepMind 一项公开的工作——一次发布、一篇论文，或者一个政策选择——是你会做得不一样的，说
  清楚你会怎么改、为什么。
- 讲一次你拒绝了一个听起来更有声望、或者薪酬更高的机会，因为它和你真正想做的工作不匹配。
- 如果你加入了这里，会让你选择离开的那一个条件是什么？
- Google DeepMind 的使命是什么？
- 你觉得 AGI 是有可能实现的吗？什么会改变你的看法？
- 你的长期规划是什么——五到十年之后，你希望自己在哪里（如果你是学生，就回答毕业之后）？

### 协作与冲突

- 讲一次你和一位研究者或技术负责人在优先级上的分歧——你们各自主张的是什么，最后是怎么解决的？
- 讲一次一位队友把你们共同做的工作全部归功于自己——你当时做了什么？
- 说一次你帮助一位新队友融入团队的经历，这个团队的背景或工作方式和这位新队友很不一样。
- 讲一次靠证据、而不是靠资历或个人意见解决的研究或技术分歧——是谁拿出的证据，结果又改变了什么？
- 讲一个需要你在研究、工程和产品之间紧密协作的项目——这几个团队各自想要的东西在哪里不一样，你是怎么
  把它们弥合起来的？

### 主人翁意识、优先级与模糊性

- 讲一次你被交办的工作超出你能完成的量，而且每个人都坚持自己那部分是最高优先级——你实际上是怎么做的？
- 说一个目标本身不清楚、或者一直在变化的项目——目标总是定不下来，你是怎么持续推进的？
- 讲一次你必须快速上线某个东西、又不能让质量下降的经历——你实际砍掉了什么，又坚持不砍掉什么？
- 讲一次你发现一位队友被工作压得喘不过气，于是采取了行动，尽管这在名义上不是你的职责。
- 说一件落在两个团队或角色之间空隙里、没有人认领的工作——你是怎么处理的？

### 领导力与团队

- 一个领导者需要具备什么样的素质？
- 管理（management）和领导力（leadership）之间有什么区别？
- 讲一次你为了赶一个紧迫的截止日期而工作的经历。
- 什么样的团队才算是一个好团队？
- 你应该和同事做朋友吗？

### 失败与反馈

- 你职业生涯里最大的失望是什么，因为这件事，你的工作方式发生了什么改变？
- 讲一次你犯的、影响到了其他人的错误——发生了什么，你又是怎么弥补的？
- 讲一次你向比你资深的人给出难以启齿的反馈——你说了什么，后来发生了什么？
- 讲一条你收到的、很难听进去的反馈，以及你后来是怎么落实它的。

### 责任感

- 讲一次你对自己正在构建的东西的风险、潜在的滥用可能，或者不公平之处提出了担忧——你向谁提出的，后来
  发生了什么？
- 说一次你必须在按时上线和完成一次安全或隐私审查之间做权衡的经历——你是怎么决定的，还有谁参与了这个
  决定？
- 如果上线一个月之后，你发现自己发表或上线的一个结果或结论是错的，你会怎么做？
- 讲一次房间里只有你一个人提出反对意见——你当时是怎么做的？

在 45 分钟里规划四到六个故事，每个三到五分钟：这个长度足够覆盖面试官的开场问题，以及一到两个追问，
又不会因为讲得太细，把下一个问题的时间也占掉。面试官在听的是故事之间是否呈现出一致的模式，而不是
某一个故事是否完美无缺，所以如果一个故事确实能回答两个不同的问题，重复使用它，代价要比硬把一个单薄
的故事撑满五分钟小。

### STAR 骨架

把每个故事的时间预算定在两分半到三分钟左右，把三到五分钟这个区间里剩下的部分留给追问。情境和任务
合起来大约 30 秒：谁参与了、你想达成什么、为什么这件事重要，只保留行动部分需要用到的事实，不铺垫
更多背景。行动大约 90 到 120 秒，是整个回答真正的内容所在：用“我”而不是“我们”来叙述，并说出你在
其中做出的两三个决策点——在哪里选了一条路而不是另一条，为什么——因为这些决策点正是追问会回过头来
问的地方。结果大约 30 秒：给出一个数字，或者一个别人也能确认的、具体可观察的结果——而不是“进展
顺利”。最后用一句话讲你学到了什么、或者事后会怎么做得不一样，把它讲成一件你后来真的应用过的事，
而不是特意为面试官加上的一句感悟。

一个只说“进展顺利”或者“团队很满意”、没有数字、也没有第三方能确认的结果，是下面每一组里最常见的
一个缺口。改法：为你故事库里的每一个故事，先写出“结果”这句话，再去写故事的其余部分；如果这句话
填不进一个数字或者一个具体可观察的结果，就把这个故事放到一边。

### 动机与使命

在考察什么：你选择 Google DeepMind 的理由，是不是真的落在你已经做过的某件事上，而不是把 HR 初筛
时说过的话，或者这家机构对自己的公开描述再说一遍。

骨架：回答“为什么是 Google DeepMind，为什么是这个团队”，用一句话说出你已经因为这个具体选择做出的
那一个决定——推掉了另一个 offer、改变了研究方向、搬了城市——再把它和你在这个岗位上会做什么连起来。
回答“安全且负责任”，在一个真实的例子上完整套用 STAR 骨架：当时有一条捷径可走的情境、你实际采取的
行动、以及结果，哪怕很小——一次你坚持要做的审查、一个你拒绝跳过的边界情况。回答你会改动的那件公开
工作，具体说出是哪一件，用一句话说清楚你会怎么改，并给出理由，这个理由要和单纯不喜欢这个结果区分
开。回答你推掉的更有声望或薪酬更高的机会，说出你选择了什么来代替它，以及为什么这件事比头衔或数字
更重要。回答使命这道题，简要而逐字地说出原话——“to build AI responsibly to benefit humanity”（“负责
任地构建 AI，以造福人类”）——把剩下的时间用来说清楚它具体改变了你工作方式里的哪一点，而不是纠结于原
话本身。回答 AGI 这道题，给出一个立场和支撑它的理由，说出哪一项证据会改变你的看法，
并说清楚不管答案是哪一种，它会怎么影响你今后的工作方式——把它当成一个考察你自己判断力的问题，而不是
一场预测比赛。回答长期规划这道题，把方向讲成一种能力或者一种影响，而不是一个头衔或者级别；如果你
是学生，就换成回答毕业之后紧接着的那一段时间。

最常见的失分方式：一个动机方面的回答，全是那几句放在哪个 AI 实验室身上都成立的话——使命远大、工作
重要——却没有任何故事支撑。改法：面试前写下那个能证明你确实感兴趣的决定，以及安全问题的那个真实
例子，这样讲出来的是一个具体的故事，而不是又把信念复述一遍。

### 协作与冲突

在考察什么：你能不能讲清楚一次真实的分歧，而不把对方讲成一个阻碍；以及你在其中的行动是不是说得
足够精确、经得起核实。

骨架：把对方的立场讲成一个理性的人也可能持有的立场，而不是一个立不住脚的靶子；说出你自己的立场，
以及把这次分歧推向解决的那一条证据或推理；说出实际的结果，如果最后是对方的想法赢了，就直接说出来。
回答被抢功那道题，直接说出你实际采取的行动——直接找那位队友谈、报告给经理，还是决定不再追
究——以及真实的后续结果，不要把队友的动机讲成一个反派。回答跨研究、工程与产品协作那道题，具体说出
每一方想要、而别的团队不想要的那件事，而不是一句笼统的“对齐很难”。

最常见的失分方式：一个冲突故事里，对方从头到尾都不讲道理，而你就是对的一方——不管事实实际上是
怎样，这样讲都会显得片面。改法：面试前用一句话说出对方的立场，这句话要是你当着对方的面也说得出口
的；再检查一下，把立场讲得这么公允之后，你的故事是不是还站得住。

### 主人翁意识、优先级与模糊性

在考察什么：当优先级本身已经没法解决两项工作之间的冲突时，你实际的行为方式是什么——你用的推理
过程，而不只是结果。

骨架：回答相互竞争的“高优先级”工作，说出你实际用来做选择的那个标准——影响力、可逆性，还是谁被它
卡住了——以及你把哪一部分降低了优先级、告诉了谁，因为悄悄放下一件事，和主动说明这个取舍，给人的
印象是不一样的。回答目标不清楚或者一直在变的情况，说出你在目标不断变化时始终坚持不变的那一件事，
以及你是怎么发现目标变了的。回答快速上线的问题，用一句话说出你具体砍掉了什么、又具体坚持不砍掉
什么，以及为什么。回答没人认领的工作，说清楚是什么让你主动接手、而不是等着被指派，以及一旦这件事
有了明确的负责人之后，你又做了什么。

最常见的失分方式：一个优先级故事讲到“我报告给了经理，我们一起想出了办法”就结束了——这回答了是谁
拍的板，却没回答你自己主张的是什么。改法：面试前用一句话说出每一个主人翁或优先级故事背后真正的
判断标准，让推理过程被说出来，而不是把它推给别人的决定。

### 领导力与团队

在考察什么：你关于领导力和团队的看法，是不是真的来自你做过的事，以及你能不能在实践里、而不只是在
理论上，把管理（management）和领导力（leadership）区分开。

回答意见类问题——领导者需要的素质、什么是好团队、要不要和同事做朋友——每题大约一分钟：用一句话给出
明确的立场，给出你自己经历里能体现这个立场的一个具体例子，说出这个立场的代价或者局限，以及你因此
会怎么做。回答管理与领导力的区别，把这个区分讲清楚：管理是通过一个正式角色去做计划、调配资源、
建立流程，并对交付结果负责；领导力是确立方向、赢得追随者，不需要任何头衔——然后给出一个你在没有
正式权力的情况下发挥了领导作用的例子。回答紧迫截止日期这道题，套用上面完整的 STAR 骨架。回答要不
要和同事做朋友，给出一个平衡的答案：朋友之间的信任和坦诚对工作有帮助，但涉及他们的决定——评审、
署名、分歧——要和这份友谊保持独立。

最常见的失分方式：一句没有例子支撑的场面话——一个谁都会同意的立场，背后却没有你自己经历里的任何
事支撑。改法：面试前给每一个意见类问题都配上一个来自自己经历的具体故事，这样立场一出来就已经有
依据，而不需要在当场被动地找补。

### 失败与反馈

在考察什么：一个你能具体说出来的真实代价，以及如果面试官没有要求你往积极的方向讲，你会不会还讲
同一个故事。

骨架：回答最大的失望，说出真实的代价——对一个项目、对一个人，还是对你自己发展轨迹的代价——以及你
此后工作方式上一个具体的改变，这个改变要能被核实，而不只是一句表态。回答影响到别人的错误，把出了
什么问题和你做了什么分开说：说出谁受到了影响、你实际做了什么弥补，以及是你自己发现了这个错误，
还是别人先发现的。回答给比你资深的人的反馈，说出你实际说了什么、结果如何，包括结果不好的情况。
回答收到的反馈，说出你事后做出的、别人也能指出来的那个具体改变。

最常见的失分方式：一个其实是优点伪装成的失败——“我太拼了”或者“我太在意结果了”——这回答的是另
一个问题，不是被问到的那一个。改法：挑一个有真实、说得出口代价的失败，并检查你说的教训，是不是
能指向后来一次你真的做得不一样的具体事例，而不只是一句感想。

### 责任感

在考察什么：你是不是真的在一个提出担忧要付出代价的情境里提出过担忧，而不只是原则上你会不会这么做。

骨架：说出具体的担忧是什么——一种滥用场景、一个公平性问题，还是对不在场的人的一种风险——以及你
向谁提出的；直接说清楚这个担忧后来怎么样了，包括它没有被采纳的情况，而不要暗示它一经提出就得到了
解决。回答速度与安全或隐私审查之间的权衡，说出当时真实的截止日期压力、你做出或主张的决定，以及
还有谁必须为这个决定签字。回答上线的结果被发现是错的，具体说出你会做的第一步——你会告诉谁，按
什么顺序告诉——而不是一句笼统的、关于透明度的承诺。

最常见的失分方式：一个没有真实风险的责任感故事——提出这个担忧不需要付出任何代价，而且明摆着会
受欢迎——这没法把你和一个从来不需要做选择的人区分开。改法：挑一个提出担忧确实要付出代价、或者
确实可能被否决的例子，直接说出实际发生了什么，包括最后答案是“不行”的情况。

### 值得反过来提出的问题

- 对于这个具体的岗位或级别，“Googleyness and leadership”评分标准里权重最高的是哪一部分？
- 如果不同面试官之间出现分歧，面试小组是怎么协调解决的？
- 这个团队最希望新加入的人能更早理解的、关于团队日常实际运作方式的一件事是什么？
- 从这一轮到最终结果，大概的时间线是怎样的？

### 故事库

从自己的经历里准备八个故事，提前把它们和上面每一组问题对应起来，让每一组都不止一个可用的选项，
整个故事库也不会到处都靠同一个故事撑着。下面的“故事类型”是一份规划模板，不是硬性规定——把每一行
换成你自己经历里真正对得上的那个具体故事。

| # | 故事类型 | 动机 | 协作 | 主人翁 | 领导力 | 失败 | 责任 |

| 2 | 一次靠证据而不是资历解决的技术或研究分歧 | | ✓ | | | | |
| 3 | 帮助一位遇到困难或者刚加入的队友尽快上手 | | ✓ | ✓ | | | |
| 4 | 通过有意识地选择砍掉什么，赶上了一个硬性截止日期 | | | ✓ | ✓ | | |
| 5 | 一个你造成的、影响到其他人的错误，以及你是怎么弥补的 | | | | | ✓ | |

### 没有故事可用时怎么办

如果自己的经历里没有任何一个故事能对上被问到的问题，直接说清楚这一点，而不要硬把一个不相关的
故事往上套——面试官识别出一个硬凑的故事，比识别出一个坦诚的空白要容易，而一个在追问下站不住的
编造情境，代价比这个空白本身更大。给出最接近的、真实存在的相邻情境，直接说明它和被问到的问题有
什么不同，然后回答这个相邻的问题。如果这个空白本身就能说明问题——比如你还没有向比自己资深的人
给过难以启齿的反馈，因为目前为止的角色还没有把你放到那个位置上——就把这一点作为答案的一部分
直接说出来，而不要编造一个没有发生过的场景。

### 准备提纲
